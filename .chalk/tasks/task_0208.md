## Background

Filed out of M8-E7's review (`task_80a4`, closed 2026-07-31). M8-E4
(`task_4c37`, PATH) and M8-E7 (`task_80a4`, `MAGPIE_FINDINGS_PATH`) were the
same defect discovered twice, one live micro-VM run at a time.

## Problem

The crun floor runs the reviewer **image**, so the OCI image config applies:
`ENV`, `WORKDIR`, and the base image's implicit `PATH` are all delivered by the
runtime. The micro-VM tier runs an **exported bare rootfs** — libkrun has no
image config to read, so none of that surface arrives unless something
re-declares it. Each missing piece fails late, inside the guest, and is only
diagnosable from guest stderr (which itself only exists because of M8-E6).

Known instances, both already fixed: `PATH` (M8-E4) and `MAGPIE_FINDINGS_PATH`
(M8-E7), each re-exported in `docker/reviewer/entrypoint.sh` under the
`MAGPIE_IS_MICROVM` guard. `WORKDIR /work` is *not* an instance — `reviewer.ts`
passes `--workdir /work` explicitly and `reviewer-microvm-argv.test.ts` pins it.

The point of this task is not to find a third live bug — as of the M8-E7 build
the surface is believed complete — it is that nothing **stops** a fourth from
being introduced. Add an `ENV` to the Dockerfile today and the micro-VM tier
loses it silently, with no test failing.

## Proposed work

- [ ] Enumerate the full image-config surface the crun tier gets and the
      micro-VM tier does not: every `ENV` in `docker/reviewer/Dockerfile`
      (currently just `MAGPIE_FINDINGS_PATH`), the base image's implicit `PATH`,
      `WORKDIR`, `USER`/uid, and `ENTRYPOINT`/`CMD` argv. Record which mechanism
      delivers each one to the micro-VM guest today (entrypoint re-export,
      launcher flag, or nothing).
- [ ] Add a **drift test** that fails when the two diverge: parse the
      Dockerfile's `ENV` lines and assert each is either re-declared in
      `entrypoint.sh`'s `MAGPIE_IS_MICROVM` block or injected by `reviewer.ts`.
      This generalises `entrypoint-tier-memory.test.sh`'s existing one-variable
      pin (which asserts the `MAGPIE_FINDINGS_PATH` literal matches the
      Dockerfile) into a check that cannot be outgrown by a new `ENV`.
- [ ] Document the contract in the Dockerfile next to the `ENV` block: "anything
      added here must also be re-declared for the micro-VM tier — see
      entrypoint.sh."
- [ ] No behaviour change expected. If the audit does turn up a live gap, fix it
      under this task and re-validate on the Pi host; otherwise the deliverable
      is the guard plus the audit record.
