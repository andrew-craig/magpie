## Background

Found during a full reinstall + live validation of `main` on the Pi host
(2026-07-30, see memory `magpie-m8-reinstall-validation`). The crun floor
validated cleanly end-to-end (live PR review posted, telemetry recorded).
The micro-VM tier does not, and this is blocker #1 of 3.

## Problem

`config.example.toml`'s pinned `[container] image` —
`ghcr.io/andrew-craig/magpie/reviewer:0.2.0@sha256:e6a6e118ce46392dffaf172afa35af2ff6c8ff375d37dd403e9d6ac77c1f3aed`
— was published under M7, **before** the M8-C4 vsock work landed
(`docker/reviewer/entrypoint.sh`'s vsock-client startup logic,
`docker/reviewer/Dockerfile`'s `vsock-builder` stage that bakes
`rust/vsock-client` into the image as `/opt/magpie/vsock-client`).

Running the micro-VM tier with the published 0.2.0 image: the guest boots,
but the entrypoint has no vsock awareness — it starts the crun-tier
`forwarder.mjs` expecting a bind-mounted `/run/gw/gw.sock`, which doesn't
exist in a micro-VM guest. It retries 5x, fails, and the container fail-closes
before Pi ever starts (correct fail-closed behavior, wrong root cause: no
image update has ever shipped for the micro-VM tier).

Confirmed the fix direction works: I locally built
`docker/reviewer/Dockerfile` from current `main` (`docker build`, no cache),
exported it to a rootfs via `docker export`, and pointed
`[microvm] rootfs_path` at it — vsock-client started, connected out over the
vsock channel, and confinement verified cleanly. The *image* is not the
blocker once it's current; only the *published, pinned* one is stale.

## Fix

Publish a new reviewer image tag/digest built from current `main` via the
existing `release-reviewer.yml` CI (multi-arch + cosign-signed, same as
`0.2.0`'s original release) and update `config.example.toml`'s digest pin.
Consider whether the version bump should be `0.3.0` given the vsock/entrypoint
changes are substantive, not a patch.

## Acceptance

- New tag published to GHCR, multi-arch, cosign-signed, verified anonymously
  (mirror the M7-2 verification steps).
- `config.example.toml`'s `[container] image` updated to the new digest.
- A micro-VM-tier live review at least reaches the vsock-connected /
  confinement-verified stage using the newly pinned image (this task doesn't
  require the review to fully succeed — see task_76b8 for the remaining
  blocker after this one).
